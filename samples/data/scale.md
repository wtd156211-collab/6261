# 百万行那份数据

规模用例不随仓库提供，按下面的参数用标准库脚本现场生成即可（生成脚本不入库），口径与 `README.md` 第 5 节一起看。

## 数据（约 26 MB）

- 100 万行，`id` 从 0 到 999999 连续；`ts` 起点 1700000000。
- 用 `random.Random(20260925)`：按行号从 1 到 999999 依次取一次 `randrange(4)`，第 i 行的 `ts` = 第 i−1 行的 `ts` 加上这个增量（先取到的增量先给前面的行，顺序不许换）。
- 行格式与 README 4.1 一致（26 字节定长、`id` 严格递增），生成出来是 `ts` 非递减的时间序列；实测这份数据的 `ts` 跨度是 1502096 秒。

## 规模查询（200 条）

第 k 条（k 从 0 到 199，`id` 写 `scale-000`…`scale-199`）：长度 `len` 按 `60`、`300`、`600` 轮换（`k % 3`），起点 = 最小 `ts` + `(k × 7919) mod (ts 跨度 − len)`，条件写 `between 起点 起点+len`。格式与 README 4.2 一致。

## 规模变更（200 条）

按 k 从 0 到 199 依次执行，每次的取值由当时表的状态定：

- k 为偶数：`append`，`id` = `1000000 + k / 2`，`ts` = 当时全表最大 `ts` + 1；
- k 为奇数：`set-ts`，`id` = `(k × 7919) mod 1000000`，新 `ts` = 该行当时的 `ts` + 3600；若加完超过当时全表最大 `ts`，改成该行当时的 `ts` − 3600（仍不为正就用原值）。

## 核对

预算与门槛在 `README.md` 第 5 节：`build` ≤ 5 s，200 条查询 ≤ 3 s、单条 ≤ 50 ms，200 次变更 ≤ 5 s，`page` ≤ 3 s；索引文件与峰值分配的上限按行数换算；整组查询平均剪枝率 ≥ 0.99、单条最低 ≥ 0.95。块容量自己定，`build --block-size` 给了就按给的来。

随仓库的小样本是 `samples/data/` 下那四份（`cut`、`part`、`edge`、`sync`），用来逐行核对结果与边界口径；规模用例只看预算与剪枝率。
